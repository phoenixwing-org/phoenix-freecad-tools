# 常用建模 MCP 与聊天 API 验收计划

状态：开发中。当前评分 **68/100**。本轮按可核验的用户任务评分，每项通过才计相应分数。现有能力作为回归基线。

## 首轮范围

- **常用建模走类型化 MCP。** 首个闭环为新建未保存文档 → 创建 Part Design Body → 生成参数可编辑的草图与 Pad → 读取尺寸和结果。先做圆环拉伸（平垫），再复用同一入口支持矩形与圆形拉伸。三种形状各有严格参数和单位，平垫输入内径、外径和厚度；仅有公称规格时先让用户明确尺寸或选定标准与系列。
- **先预览，再确认。** 在同一套预览、原生确认、状态查询流程中添加严格的新建分支。无文档也能预览；预览列出新文档、对象和尺寸。确认前零写入，确认时复核窗口、服务和文档上下文。验证实体和尺寸后报告结果。撤销覆盖 Body 中的建模事务，新文档壳可能仍保留。打开其他文档、保存、任意对象类型、任意属性和代码均不属于这个新建分支。
- **脚本保留给显式授权的高级操作。** 外部完整模式已有 `execute_script`，可探索少见操作或生成原型。内置聊天使用类型化接口。同行有类似的分层做法，FreeCAD MCP 同时提供创建与脚本入口，Unity MCP 将对象操作和脚本操作分组。[FreeCAD MCP 工具清单](https://github.com/neka-nat/freecad-mcp/blob/main/docs/tools.md) · [Unity MCP 核心工具](https://coplaydev.github.io/unity-mcp/reference/tools/core/)
- **聊天面板提供三种连接。** Codex 保留默认的 ChatGPT 登录，并增加 OpenAI API Key 登录。两者共用现有 Codex app-server 和受限 MCP；API Key 登录在 Codex 端使用独立的内存认证，按 OpenAI Platform 的项目额度和费率计费。先用锁定版本和合成响应验证认证协议及工具调用。[OpenAI 官方认证说明](https://learn.chatgpt.com/docs/auth#sign-in-with-an-api-key)
- **DeepSeek API Key 直接请求 DeepSeek。** 独立 API 适配层复用聊天界面和本窗口的受限 MCP。齿轮中选择 DeepSeek、填入 Key、测试连接后选模型。纯聊天开箱只需要 FreeCAD 插件和 DeepSeek API Key；没有 Codex 安装或 ChatGPT 账号也可使用。启用 FreeCAD 工具时才连接本窗口的受限 MCP。先验文字收发及停止，再验只读工具与原生审批。其他兼容服务可沿用直连适配合同，作为可选项逐服务验证。[DeepSeek API 文档](https://api-docs.deepseek.com/quick_start/agent_integrations/)
- **连接与数据按服务隔离。** 切换前断开旧连接，使用独立会话；显示接收消息和工具结果的服务。直连 API 默认在连接测试成功后按服务商与 HTTPS API 地址记住 Key，可选择单次使用或清除。macOS 和 Linux 使用当前用户专属权限的文件，Windows 使用当前用户 DPAPI。Key 不进入 FreeCAD 偏好、普通配置、命令行参数、日志、历史或 MCP 工具进程。真实调用只由用户在独立测试环境发起。

## 直连聊天参考与验收

- FreeCAD AI 把模型服务设置放在聊天齿轮里，并提供类型化、可撤销的建模工具。ChatCAD 的多服务接法将 API 地址、Key 和模型分开；Chatbox 则把这些设置放到服务商预设中，提供连接测试和选模。采用预设流程，FreeCAD 工具为单独开关。[FreeCAD AI](https://github.com/ghbalf/freecad-ai/blob/master/Resources/Documents/Overview.md) · [ChatCAD](https://github.com/vcdim/chatcad#4-configure-your-provider) · [Chatbox 的 DeepSeek 设置](https://chatboxai.app/en/guide/byok/deepseek)
- 首批固定 DeepSeek 官方 HTTPS 端点，按 Chat Completions 协议异步收发。工具模式用本地 MCP 的明确清单及参数校验来处理模型函数调用；模型服务只接收必要的工具结果。建模仍由 FreeCAD 原生确认。先验不含 Codex 可执行文件、无登录凭据的独立配置，再验账号实测。[DeepSeek 工具调用](https://api-docs.deepseek.com/guides/tool_calls/)

## 推进和收尾

1. 先做圆环拉伸并接入内置 Codex，从空白窗口验证完整链；随后沿用同一入口补矩形和圆形。
2. API 模式与建模并行开发。先用合成端点验证调用链，真实账号验收由用户参与；启用工具时沿用本窗口身份、工具白名单和原生确认。
3. 每轮按表更新得分与证据类型，区分源码、自动化、原生运行和人工验收。独立中性样件可入库，真实工作数据、凭据和原始运行回执留在仓库外。
4. **达到 90/100 即结束本轮。** 无文档新建、三种形状、写入边界、三种聊天入口、API 隔离和人工验收须全部通过。剩余项记待办。复杂草图、阵列、装配和更多服务商留给后续按实际需求立项。发布另行决定。

## 本轮核验记录

- **20 分 · 常用形状。** 在独立 FreeCAD 1.1.4 实例通过原生确认按钮创建三种中性样件，核对命名驱动尺寸、完全约束、精确拓扑包围盒、单一有效实体、体积以及圆环通孔；分别完成撤销和重做。
- **5 分 · 预览与取消。** 三种轮廓在预览、等待和取消后均保持零文档。直接应用被拒绝。合成回归检查打开无关文档后旧确认失效。
- **10 分 · 无文档新建。** 使用正式 MCP SDK 及聊天范围的实际 stdio CLI，从空白窗口创建三种未保存文档；经 MCP 读取确认 Body 和未保存状态。
- **10 分 · 其余写入边界。** 实测原令牌重放、原生取消、伪确认、过期和更换目标拒绝；验证发生几何反验失败时回滚建模节点并留下未保存的空文档。三种零件均验证了撤销重做。
- **10 分 · 自动化与原生回归。** 类型检查与构建、Python 2307 项、Node 403 项通过。两个隔离 FreeCAD 窗口经正式 SDK 验证跨服务令牌拒绝及旧试用插件缺能力时明确拒绝。
- **DeepSeek 直连文字链已通过合成验收。** 在独立 FreeCAD 原生面板留空 Codex 路径，验证服务切换、遮盖并清空 Key、测试连接、选模、收发、停止和会话隔离。真实 Qt 请求使用固定 HTTPS 地址和手动重定向策略；测试用合成响应，未访问真实账号。Python 2312 项通过。本项待补受限 MCP 和实际账号测试后计分。
- **DeepSeek 受限 MCP 合成验收。** 在独立 FreeCAD 原生聊天面板，经真实 Node stdio 连接当前窗口。模拟模型先调用连接状态、列文档，再预览圆环并请求原生确认。确认前零文档；原生确认后，下一条消息经原 token 反验返回已应用且未保存。自动化覆盖工具清单异常、身份变化、未知工具、参数与重复调用边界、超时和晚到结果。尚缺真实账号收发与人工验收，本轮分值维持 55/100。
- **OpenAI API Key 认证与界面。** 独立临时配置固定官方 API 地址，通过锁定 Codex app-server 的 stdin 提交 Key，并以账户回读确认 API 模式。首个成功回复后才按服务商和地址保存可选 Key。聊天中的 AI 回复采用原生 Markdown 显示，服务身份显示与模型自述分开。在原生 FreeCAD 验证合成 Key 认证、临时配置清理和窄面板 Markdown 显示。在 macOS 原生 FreeCAD 复测窄面板 Markdown 表格、行内代码和退出。
- **8 分 · Codex · OpenAI API Key。** 人工试用界面显示 OpenAI API、实际模型和 FreeCAD 工具模式。完成真实收发，读取当前窗口的空白状态，并取得带运行时来源的建模预览。
- **当前候选回归复验。** 同一源码快照通过 TypeScript 检查和构建、Node 403 项、Python 2351 项（其中 1 项原生 Windows DPAPI 测试在 macOS 跳过）。本轮沿用既有独立 FreeCAD 的旧版拒绝、双实例归属及三种形状的验收证据。
- **5 分 · 候选包和帮助。** 0.4.2 本地 Addon ZIP 和 npm tgz 已核对版本、成员路径、源码、构建字节和隐私边界。使用解包后的插件和 CLI，经真实 MCP stdio 与 FreeCAD 原生按钮，核对平垫完整预览、取消、确认、结果反验、撤销重做及未保存。安装与内置帮助补有操作和限制。旧试用包保留，候选未发布。
- ChatGPT 登录和 DeepSeek 实际模型复验、完整 API 凭据隔离、自定义兼容服务及平垫人工验收继续待验。自动点击的原生测试不计用户亲自验收。
