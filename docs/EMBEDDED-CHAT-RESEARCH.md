# FreeCAD 内嵌聊天：官方通道与设计边界

Phoenix Tools 使用原生 Qt 控件提供独立聊天面板，消息协议由官方 Codex app-server 处理，FreeCAD 能力通过 MCP 适配。本文只记录公开接口、源码职责和后续验收要求；使用步骤见[聊天操作](CHAT-USAGE.md)。

## 认证与会话

认证接入参考官方 [Sign in with ChatGPT 本地/开源应用说明](https://developers.openai.com/siwc/token-sharing-open-source)和 [Codex App Server](https://learn.chatgpt.com/docs/app-server)。认证、模型访问和账户权限以官方接口为准；登录能力不等于获得桌面聊天历史或控制其他会话的权限。

本插件的聊天使用独立 profile，由官方子进程管理认证。插件不读取或复制默认客户端的凭据、cookies、聊天存储或私有 socket。用户显式连接、登录和发送，路径、消息及会话标识属于本机运行数据，不进入源码、示例或验收文档。

当前产品不实现桌面活动会话的镜像或接管。共享会话需要明确的官方 endpoint、线程绑定、事件订阅和并发控制合同；同一账户或同一个线程 ID 不能证明多个客户端可以同时控制活动 turn。

## Qt 与进程分工

原生 Qt 聊天无需网页嵌入。`pft_chat_views.py`负责界面，`pft_chat_controller.py`负责协议与状态，`pft_chat_qprocess.py`负责应用拥有的异步子进程；专属配置与路径设置分别由 profile/settings 模块处理。

QWebEngineView 是另一种界面选择，是否可用取决于目标 FreeCAD 发行包。兼容层文件存在不足以证明原生扩展可用；网页方案须单独检查依赖、导航、认证及会话边界，不能要求替换宿主 Qt 来满足插件需要。

请求 ID、连接代际、有界缓冲和截止时间用于隔离迟到事件。关闭 Dock 与结束自有子进程分别处理；终结回调须幂等，不访问已销毁的 C++ 对象。协议允许在同一请求内恢复时，仍沿用原截止时间，不自动重发用户消息或创建新 turn。

## MCP 权限与协议

支持的 app-server 版本及字段以客户端代码约束和正式协议为准。应核对有效配置、完整工具清单及每次实际响应，不能仅凭参数已发送就认定策略生效。模型选择应与会话响应的实际型号和 provider 一致；不匹配时停止发送。

纯聊天要求其 MCP 清单为空；FreeCAD 工具模式使用精确白名单，Desk 数据工具须另行明确启用。文件只读策略不能约束 MCP 服务对 FreeCAD 的修改，工具声明和提示词也不能替代原生目标、事务及写后校验。

聊天不提供任意 Python 代码入口。类型化外观调用复用工作台规则和桥接请求去重；改名、属性及设计写入需要各自完整预览与确认流程。验收应分别核对工具事件和独立样例结果，不能从助手文字推断操作已经执行。

## 会话恢复的后续要求

**插件自有持久会话与明确选择恢复已有候选源码和自动化。** 原生界面已用独立本地合成协议进程验证新建、退出后恢复及继续、活动历史只读；真实官方认证／持久存储和跨进程恢复仍待独立验收。以下合同保留，不能把模拟协议通过当作官方服务验收；桌面活动会话共享仍单独研究。

- 默认继续使用临时会话；用户明确开启“保留新聊天”后，才为新会话请求 `ephemeral:false`。需说明持久历史可能包含 CAD 工具返回的数据，不能声称只保存文字。仅登记本插件创建的线程 ID、时间、实际模型及策略范围，由用户选择；不扫描默认客户端目录、列举桌面历史或认领未登记线程。关闭保留选项不自动删除既有历史，已有临时会话也不自动转换。
- 已核对的 CLI 0.160.0及新增0.167.0-alpha.3.2生成协议中，`ephemeral`、`thread/resume` 的 `excludeTurns` 为稳定字段；稳定及实验 schema 均不含 `persistExtendedHistory`，不得猜测发送。`historyMode` 是实验字段，首版不启用实验接口，检查服务实际返回模式。登记与恢复绑定实际CLI版本，不跨版本迁移。按官方[创建与恢复合同](https://learn.chatgpt.com/docs/app-server#start-or-resume-a-thread)，恢复请求采用 `excludeTurns:true`；元数据先经 `thread/read` 核对，历史在resume之前只读载入并复核元数据；全部终态且策略通过才resume，最终再确认idle。历史使用[回合分页](https://learn.chatgpt.com/docs/app-server#list-thread-turns)和[条目分页](https://learn.chatgpt.com/docs/app-server#list-thread-items)，保持字节、条数及游标上限，未载入部分明确显示。候选每页20项、turn/items共享20页及60秒总预算；另限100回合、256条文字和256KiB，超限只读。
- 每次连接重新核对认证、模型清单、有效配置及 MCP 范围。恢复时显式声明模型、provider、工作目录、沙箱、审批和开发者指令，再核对恢复响应及线程级 MCP 精确清单。`config/read` 没有线程 ID 参数，不能独自证明恢复线程的有效策略。原模型不可用或实际返回不匹配时停止发送，由用户明确改选，不静默回退服务默认。
- 同协议独立进程的持久租约及Qt退出接线已经实现，并通过独立macOS合成进程验收，见[操作边界](CHAT-USAGE.md#专属进程登记)；这不是历史恢复完成或旧版进程发现证明。后续持久会话必须继续满足单 writer：启动前登记，短时内核互斥保护更新，已退出PID的有效登记已有显式检查/原生确认清理入口；存活或未知残留与旧版本过渡仍需分别处理。父进程退出只会释放内核锁，不能证明子进程已退出。`stop()`、kill 请求及 QObject 删除均不释放进程租约；仅精确自有进程的确认退出，或已确认从未启动的失败，才能释放。存活、未知或损坏登记不自动清理、接管或另换 profile 绕过；不得按登记 PID 杀进程。
- 历史通过独立 reducer 生成展示数据，不调用当前回合完成处理器，以免旧失败终止新连接。按线程、回合及条目 ID 合并快照，终态不被迟到进度覆盖。增量文字没有通用事件序号，不按相同文字删重；重连后重读快照，不重放旧 delta。保留失败/中断标识，时间缺失时不伪造当前时间或首包耗时；只安全展示用户／助手文字与回合终态，不载入工具参数、结果、图片、路径或原始错误；文字本身仍可能包含CAD数据。
- 恢复后若回合仍在进行或状态不明，先显示并核对原回合状态，禁止自动补发消息、重复调用工具或创建替代回合。旧失败与中断可展示为历史，不能当作新的执行授权；只有当前空闲状态及全部策略检查通过，用户才能显式发送下一条。

验收需在独立配置和合成输入下，人工完成官方认证，验证持久新建、真实退出、重新启动、历史恢复及继续收发/停止；另覆盖父进程崩溃但子进程存活、重复启动、启动失败、模型或 MCP 变化、未完成回合、分页重叠及迟到事件。单元测试不替代真实认证与进程验收，单个平台通过不代表跨平台可用；独立恢复成功也不证明可以接管桌面活动会话。真实账户、聊天、配置、进程输出和宿主操作经过不作为公开样例。更多权限和界面边界见[聊天操作](CHAT-USAGE.md)，后续工作见[TODO](TODO.md)。
