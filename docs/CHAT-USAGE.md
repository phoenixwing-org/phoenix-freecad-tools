# FreeCAD 原生聊天

通过 Phoenix Tools → **AI 聊天** 打开原生 Qt 面板，无需 QtWebEngine。支持纯文本和受控FreeCAD MCP两种模式；启用工具后可以读取当前文档、操作视图及设置明确目标外观。Label/BOM/Link修改已在独立样件走通MCP及原生确认，聊天事件流和异常回滚仍待验；有限首个Pad Length源码已接入同一确认链，范围见[合同](PAD-LENGTH-EDIT.md)，独立MCP链已有原生样件测试，内置聊天完整链仍待验收。

1. 点击首行右侧齿轮“聊天与工具设置”，核对自动发现的Codex执行文件，或浏览选择绝对路径。配置集中在这里，主面板只保留聊天和必要连接引导。
2. 需要操作 CAD 时，展开“聊天与工具设置”，填写 Node 22 或更新版本的绝对路径及已构建 Phoenix MCP 包的 `dist/cli.js`，勾选“启用 FreeCAD 工具”，保存。先启动工作台 MCP 桥接；该设置不会下载、编译或启动桥接。
3. 点击“连接 Codex”。仅此时创建 FreeCAD 用户数据目录下 `PhoenixTools/CodexChat` 专属配置和工作目录，并启动本窗口拥有的 stdio 子进程。
4. 未登录时点击“使用 ChatGPT 登录”。面板先显示“正在获取登录链接…”，取得并验证官方链接后才请求系统浏览器打开，再等待登录完成。若浏览器没有出现，可在本次登录等待期间点击“重新打开登录页面”或“复制登录链接”，手动在浏览器中打开；这些操作复用同一次登录，不重新发起登录请求。链接只在控制器内存中暂存，不进入普通状态快照或日志，完成、取消、超时或断开后清除。插件不要求 Platform API Key，不复制桌面应用的凭据或 cookies；即使 Codex 桌面端已登录，首次使用本插件的专属配置仍需单独登录。
5. 输入消息并点击发送；回复逐步显示。停止按钮请求中断；失败不会自动重发。中断或失败的回复在时间旁保留“已停止／未完成”，后续成功回合不抹除旧标识。终结事件单独报告失败时也按认证、额度、网络或模型原因脱敏提示并停止本窗口连接，未知原因保持通用提示；不显示服务原始错误正文。模型服务标记 `willRetry:true` 的连接恢复在同一个请求内继续，仍受原回复超时限制，不创建新 turn 或重发用户消息。不可恢复的网络/登录/额度/模型错误使用明确脱敏提示。关闭或断开只停止本窗口创建的子进程，不停止 Desk 或 FreeCAD MCP。若 Qt 已确认该自有失败子进程停止，但退出信号未送达，下次手动连接会清退其残留包装；仍运行或状态不明的进程不会被接管或重启。

首行三个紧凑图标分别调用现有当前文档工具、轴测Fit及外观命令；右侧Phoenix图标切换到Phoenix工作台，齿轮折叠Codex路径、工具开关/Node/CLI、断开、模型/字号、复制提示/官方说明/关闭以及桥接和工具诊断。错误状态可选中文字，也可点击小复制图标取得错误代码与脱敏说明。断开或报错时主面板显示“连接Codex”，未登录时显示官方登录，连接可用后这些便捷按钮收起。打开齿轮、调整字号或使用CAD快捷图标不自动断开或创建新会话。面板最低宽约300逻辑像素，长模型名/路径不撑宽，设置过高时纵向滚动。

聊天可从 **工具 → Phoenix → AI 聊天** 打开，不必先切换Phoenix工作台。文档、轴测Fit和外观图标调用同一组已注册的原生命令；外观窗口独立持有本次预览快照和事务，多个入口唤起同一活动窗口，不复制或接管它的预览状态。聊天与进程的Qt信号使用各自持有的QObject接收器，关闭外观窗口不负责断开聊天或释放聊天进程。

版本说明：当前源码候选为 **0.4.1（待发布）**，最后已发布版本仍为0.3.2。旧0.4.0–0.10.0是[未发布内部迭代标签](VERSIONING.md)，保留当时语义；历史运行回执不随源码分发，当前验收范围和实际包状态以[验证记录](VERIFICATION.md)为准。

当前未发布候选明确支持 Codex CLI **0.160.0** 和 **0.167.0-alpha.3.2**，其它版本仍拒绝，不以版本号大小推断协议兼容。客户端更新后，旧插件可能因固定版本检查而拒绝连接；需要对应的兼容修正。登录身份、模型访问和用量由官方服务决定，不能保证任何账户都有指定模型权限。本窗口默认创建临时会话；已有明确开启的插件自有持久会话与选择恢复源码，真实官方认证后的跨进程恢复仍待独立验收。桌面当前会话复用和多窗口并发接管尚未实现。

## 连接状态与后续修正

本机app-server连接、官方登录、模型回复是三个独立阶段。未登录时正常连接应显示登录入口；这不代表模型网络请求已经通过。登录失败或发送后的连接恢复须按实际阶段诊断，不能通过重新发送原消息来判断成功。

0.3.2之后的开发分支已修正两项连接边界：初始状态回调关闭或重连后不启动旧代子进程；官方0.160.0稳定响应省略可选`account`时保守显示需登录，仍拒绝缺少必需布尔字段的无效响应。已知传输错误保留固定脱敏代码，原始诊断、代理值、登录链接和凭据不加入普通状态或文档。这些修正尚未进入已发布的0.3.2安装包，实际原生验收范围见[验证记录](VERIFICATION.md)。

专属 profile 强制 ChatGPT 登录，官方客户端凭据存储限定在该 profile 文件中，目录仅当前用户可访问。已有未知目录或改动配置会保留并拒绝覆盖。插件不直接读取凭据内容，官方 app-server 负责认证持久化。关闭面板不会删除登录配置；在提供正式退出/清理界面前，不自动清理此持久目录。

## 专属进程登记

本候选的新连接会在专属profile使用私有进程登记和短时内核锁，避免采用同一协议的多个客户端同时写入该profile。启动前登记，原生started后记录自有PID；只有精确自有进程的真实退出、明确未启动的失败，或同一Qt进程对象确认NotRunning，才能释放。停止请求、关闭Dock、QObject销毁或父进程退出都不等于子进程已经退出。立即停止后即使晚到started，也不发送排队消息，而是停止刚确认运行的同一个自有handle。

发现既有、损坏、权限不符或状态不明的登记时拒绝新启动，显示固定脱敏提示；不删除登记、不按登记PID杀进程、不因时间久或父进程死亡而自动接管。意外退出后可在聊天齿轮设置中点**检查聊天进程登记**；仅当本协议的有效running登记所记录PID当前不存在时，才显示默认取消的本机清理确认。确认后在同一锁内重验原登记和PID，只移除这一笔登记。取消、Esc、关闭或确认期间连接代际/状态变化都不清理；PID仍存在（包括可能已被复用）、权限不足、launching无PID、损坏或未知登记继续拒绝。检查不创建profile、目录或锁；清理不启动服务、登录或重发消息，成功后由用户手动连接。重启应用本身不能被当作清理授权。正常退出后下一次手动连接可继续使用原专属登录配置，不迁移或读取认证内容，清理操作本身不恢复聊天历史。

存在性观察仅使用正整数PID的`kill(pid,0)`；[macOS系统合同](https://developer.apple.com/library/archive/documentation/System/Conceptual/ManPages_iPhoneOS/man2/kill.2.html)说明信号0只作检查，ESRCH表示未找到该PID，不能据PID仍存在证明原进程身份。清理后若目录持久化或反验失败，明确报告结果不确定；登记可能已经删除，先重新检查，不能声称已成功或文件必然仍保留。

此约定仅覆盖实现该登记协议的新进程，不能证明升级前尚未登记的旧版子进程不存在。已有v1配置保持兼容，升级前仍须通过原客户端正常断开并确认其自有子进程退出，不能把首次登记成功当作对旧进程的发现或排他证明。文件适配目前要求POSIX私有权限、单链接文件及原生flock；Windows缺少已验证的ACL/锁适配时明确拒绝聊天启动，Linux尚待独立原生验收。它不影响普通CAD工具或MCP桥接。

纯聊天阶段关闭 shell、执行、应用、插件、hooks、多代理、Web 搜索等已核对开关，使用只读文件策略并拒绝客户端审批请求。发送前先用 `config/read` 核对合并后的有效配置（登录方式、凭据存储、provider、沙箱、审批、Web 与八个功能开关），再逐页检查全局及新线程 MCP 清单。纯聊天要求为空；工具模式要求只有 `phoenix_freecad`、精确的 Node/CLI/本机地址与默认22工具白名单（显式Desk数据模式为27项），并要求线程状态 connected。全局未报告状态不被当作已连接。未报告的 `view_image` 保持未知，不把 CLI 设置等同实际禁用证明。**这些设置不构成完整的本机文件读取隔离**：没有证据证明所有内置读取工具被穷尽禁用，看到工具事件后断开也不能撤销已经发生的服务端操作。开发者指令限定工具用途，它是行为约束，不是安全沙箱。当前不自动附加 CAD、工程路径或文档内容；用户请求 CAD 操作后，工具读取的模型信息会发送给模型服务。MCP 本身可以操作 FreeCAD，文件只读策略不约束其外观写入。

实现分为配置/文件适配、无 Qt 的状态 Controller、QProcess JSONL 传输和 Qt View。输入单条16 KiB，会话显示文本256 KiB，入站JSONL单行1280 KiB、出站队列512 KiB，记录条数与嵌套有界；请求、登录、回复和中断分别限时。纯文本回合总时限120秒，MCP回合300秒，从发出 turn/start 起固定计时；工具进度与连接恢复不续期。协议错误、非预期工具、超限及进程退出明确失败，只清理自己创建的进程。

右侧原生停靠与浮动已实现。改名、Link名称同步及BOM属性修改已在独立样件完成MCP与原生确认测试，聊天事件流、用户手工和异常回滚仍待验收。布局偏好、更多CAD建模工具、官方持久会话端到端验收和正式Sign in with ChatGPT方案仍在后续计划。依据：[官方 Codex App Server](https://learn.chatgpt.com/docs/app-server)。

后续可研究在FreeCAD显示和操作同一桌面会话，当前产品尚未支持。官方共享 app-server/Unix socket 能力与“当前桌面应用导出第三方 attach 入口”是不同合同；后者尚未找到足够证据。先打通现有独立原型，镜像/共享会话继续研究，不读取私有桌面 socket、cookies 或其它会话。

## 保留与恢复本插件聊天（候选）

默认不保留新聊天。需要时，在齿轮设置勾选 **保留新聊天**，点击“保存聊天设置”，下次手动连接生效；当前临时会话不会转换。官方客户端可能把消息与 CAD 工具返回的数据写入专属 profile，不限于界面展示的文字。关闭选项不删除已有会话。不要将专属 profile 放入工程、插件或源码目录；持久模式在已识别的本插件源码／Addon 内会拒绝启动。

恢复时先正常断开并等本窗口子进程退出，再点 **读取本插件保存的聊天**，选择时间与模型对应的一项，点击“连接 Codex”。列表读取只检查专属目录内本插件的登记，不启动进程、读取正文或自动连接；选择旧会话明确表示继续该持久会话，与“保留新聊天”开关分开。打开面板、展开设置和保存偏好均不读取历史。没有登记的桌面或其它线程不会列出或认领，不调用全局 `thread/list`。

本插件登记只含线程 ID、创建时间、实际模型、策略范围指纹、历史模式、CLI版本与provider；登记另绑定实际专属目录身份，私有权限与字节／数量有界。正文由官方客户端保存在专属 profile，登记不是聊天备份。未知、改动、复制的登记或不兼容配置均拒绝，不迁移或覆盖。登记失败时，服务可能已创建空会话，但不会发送第一条用户消息；不要将未确认登记说成持久历史已可恢复。

每次恢复重新读取当前认证及模型目录，核对原模型、当前配置与精确 MCP 范围；范围或型号变化即拒绝，不静默换默认。先用 `thread/read` 核对登记元数据，再通过 turns/items 分页只读载入，第二次读元数据；全部旧回合完整且终态、未见活动后才 `thread/resume(excludeTurns:true)`，重新声明模型／权限／开发者指令，核验线程 MCP 清单并最终确认 idle。`notLoaded` 表示未载入，不能作为空闲证明。不会自动发送消息、续写中断请求或重放工具调用；下一条由用户明确发送。

协议按上述两个明确版本分别核对，只有服务实际返回 `historyMode:paginated` 的已登记会话可恢复。登记、范围指纹及线程元数据使用实际CLI版本，恢复必须与当前运行版本一致；跨版本保留旧登记并拒绝，不自动迁移或读取历史。不发送实验 `historyMode` 请求或不存在的 `persistExtendedHistory`；旧模式、缺接口及不兼容响应明确停止，不回退到其它历史来源。每页20项，turns/items合计最多20页、恢复总60秒，另限100回合、256条文字和256KiB文字。超限或仍有活动／未知状态时只显示已核对部分并禁用发送，不把部分历史说成完整。较长的正常会话也可能达到此候选的限制。

历史只显示用户／助手文字及失败、中断标识，不重新展示工具参数、结果、路径、图像或原始错误；文字本身仍可能包含 CAD 数据。使用条目记录的UTC时间，缺失时留空，不伪造当前时间或首包耗时。旧失败不会当作新回合失败。当前原生验证使用独立本地合成协议进程，尚未完成真实官方登录、持久存储及跨进程恢复的端到端验收；桌面活动会话共享与跨平台适配仍待办。协议依据：[恢复线程](https://learn.chatgpt.com/docs/app-server#start-or-resume-a-thread)、[分页回合](https://learn.chatgpt.com/docs/app-server#list-thread-turns)、[分页条目](https://learn.chatgpt.com/docs/app-server#list-thread-items)。

## FreeCAD 工具模式

未发布候选在既有明确的工具开关下增加三个图纸PDF导出入口，基础聊天22项，显式Desk为27项；正式0.3.2仍为19/24。PDF需在原生面板捕获预览、选择路径并最终确认发布，AI参数不接受路径/确认/覆盖。增加工具会改变配置与持久会话的范围指纹；旧19项配置或登记不静默扩权，不迁移旧登录或自动建立替代会话。macOS受限单页已通过正式SDK/原生确认链自动验收；真实官方模型聊天调用和用户手工操作仍待验，见[合同](TECHDRAW-EXPORT-PLAN.md)。

连接配置只写本插件的 FreeCAD 偏好，不改默认 Codex 配置。专属 app-server 使用进程参数注册 Node MCP；Node端默认仅注册22个工具；显式Desk数据模式增为27项，双层核对白名单和准确env，不开放脚本或直接apply；Label/BOM修改必须原生确认。工具调用名称与执行中/已返回/失败显示在齿轮设置中的诊断区，空清单隐藏，不从助手文字推断操作成功。

Addon ZIP只更新FreeCAD中的Python插件，不会替换聊天设置原先指向的Node MCP。升级后须分别核对插件、Node包及其实际工具清单；只有文件存在或包名正确不足以证明兼容。出现“FreeCAD MCP 服务或工具清单不符合约定”时，检查齿轮设置中的MCP CLI是否来自配套的已构建发行包，并在正常断开后重新连接。不要为消除错误而放宽清单或复用旧schema，也不要依赖临时开发目录作为持久安装位置。

- 连接与读取：能力、连接、打开文档、文档/对象/选择、缓存几何和 TechDraw 摘要；`inspect_design` 读取明确对象的 Body Tip、约束、自由度、特征参数和表达式缓存。未知值保留 null，角度 datum 使用 deg；不求解、不重算、不沿 Link 读取来源。
- 相机：Fit、轴测图和标准视图。
- 外观：`set_appearance`，显式文档及1–100个内部对象名，随机配色或0–100%透明度。`operation:set_transparency` 要求整数 `transparency`，旧 `half_transparent` / `opaque` 保持兼容。复用本地完整材质快照、事务、写后复核；可撤销，不重算、不保存。Link 限制同[当前文档工具](CURRENT-DOCUMENT-TOOLS.md)。
- 去重：外观请求携带 requestId；未完成时查询原 ID 的 `get_script_status`，不新建请求重复写入。去重范围为当前桥接服务会话。

此模式不注册任意脚本、截图、选择/显隐、重算或直接apply。改名和BOM属性先完整预览，再由用户在FreeCAD原生窗口确认；MCP参数不能确认。完整外部 MCP 客户端仍有原有高级能力。示例：“先检查连接及活动文档、Body、Tip和编辑状态，然后把我明确指定的对象设为随机颜色及半透明，不保存。”修改前先确认目标，不以显示名代替内部 Name。

更新Node代码后，已有客户端进程会保留先前工具schema，需断开并重新连接以取得新参数。工作台按钮使用当前已加载的Python模块，二者分别核验。

聊天默认使用精确22工具清单，设计诊断和约束分页须按接口合同验收。更新Node代码后要重新建立MCP子进程；同时更新Python时，已打开面板仍持有旧Controller，磁盘文件不会自动替换它。已加载面板不会因磁盘源码更新自动替换Controller；通用升级按安装说明进行，不承诺自动热更新。

## 模型与字号（已纳入0.3.2）

打开“聊天与工具设置”。连接并完成官方登录后，面板通过 `model/list` 读取当前客户端/账户提供的清单，可手动刷新。列表每页20项、最多5页/100项、总30秒，仅显示可用于文字且非隐藏的条目；不把固定模型名写成通用可选项。依据：[OpenAI官方模型列表协议](https://learn.chatgpt.com/docs/app-server#list-models-modellist)。

“服务默认”不发送具体型号。选择列表中的型号后，开始会话时请求该 `model` 值，并核对实际返回型号和 `openai` provider；若不一致就停止，不发送用户消息。已核对的两版稳定协议未包含 `allowProviderModelFallback`，当前不发送该字段，选模保护依靠实际返回值门禁。已保存的候选每次连接重新验证；不可用时明确提示，必须自行改选，不能静默换成默认。清单读取失败或超时仍可明确选服务默认聊天；列表是元数据，可选计时回调不会杀掉连接，正常请求/回复超时仍会结束本窗口的连接。

模型在第一条消息建立会话前可以修改；之后锁定，直到新连接。不会自动重置正在运行的会话，也不迁移旧临时历史。下拉框与刷新在已开始会话时禁用；当前实际使用型号显示在清单状态下。

字号可选8–32磅或“跟随 FreeCAD”，选后只改变聊天记录和输入框，回复中也可调整；不会修改全局字体、CAD或其他窗口。“保存聊天设置”持久保存模型候选和字号，失败整笔恢复原值/缺失键。模型候选只代表用户选择，保存不等于账户有权限。

已运行面板持有创建时的Controller，更新后按[安装说明](ADDON-INSTALL.md)加载新代码；不承诺自动替换现有连接或热更新。


## 可选Desk数据工具

先在Phoenix Tools的Desk连接设置中配置已有Node、正式CLI和私有状态目录。聊天gear里“启用Desk数据工具”默认关闭，须先启用FreeCAD工具；明确保存后下次连接生效。仅在保存/连接且开启时读取验证已有Desk配置，不探测或启动后台，不读取当前/最近工作空间。

开启后，27工具清单包含`desk_get_connection_status`、`desk_search_index`、`desk_query_references`、`desk_query_cached_metadata`和`desk_get_cached_thumbnail`。用户请求核对能力时，可在连接工具显式设置`includeRuntimeFeatures=true`；它仅观察缓存支持/Native门禁，不授予执行权限或探测最近空间。每次数据查询指定明确workspace，数据来自Desk已保存索引或缓存，不能代表FreeCAD未保存内存、完整依赖新鲜度或实物数量；不启动CAD、扫描、生成或修复作业。模型/工具配置、effective env与实际工具库存严格核对，五项Desk工具还须有正确的只读注解，缺失不静默降级。

聊天工具选项、模型与字号现在复用原生偏好保存helper：写入及RAM回读后调用`App.saveParameter('User parameter')`，失败完整恢复原值/缺失键，恢复不确定时明确报错。原生API会保存整个用户参数集，不保存CAD；磁盘持久化和GUI信号验收分别记录，不用合成测试代替真实API证明。缓存另需cad.cache.read v1运行能力，元数据缺失不生成、图片须绑定精确revision；完整数据语义见[能力共享](DESK-MCP-CONTRACT.md)。

缓存单图MCP结果最多1MiB。聊天入站JSONL单行1280KiB（含协议包装），单次原始读取批次最多两倍；发送队列仍独立512KiB、stderr累计16KiB，JSON深度/项目限制保持。超限明确停止，不丢弃部分消息；多图聚合事件也受单行界限。工具图像只供模型结果流消费，聊天状态/记录仅保留工具名称与状态，不嵌入base64。

## 改名与属性的人工确认

明确请求改名、Link名称同步或BOM字段修改后，AI先调用`prepare_part_changes`展示全部对象/字段的旧值、新值、来源和冲突。适用且有变更时，`request_part_change_approval`打开非模态原生窗口；你核对完整差异后点“确认修改”，才会调用工作台事务。取消、Esc、关闭和过期不执行；不会自动保存。

AI收到`awaiting_confirmation`应请你检查窗口并等待，不能声称已修改，也不应忙轮询。确认后在聊天回复，AI用原token调用`get_part_change_status`；`applied`才报告应用结果，`native_confirmation`另表明是否经过原生按钮。超时先查原token，不新建预览规避未知状态。原生确认与官方客户端审批是不同通道，客户端执行审批仍被拒绝。详见[原生确认链](NATIVE-PART-APPROVAL.md)。


## 聊天连接与系统代理（后续修正，尚未发布）

无显式HTTP/HTTPS/ALL代理环境变量时，受支持的专属Codex进程主动启用`respect_system_proxy`，由官方客户端按目标URL解析系统规则。插件不提前读取、转换或拒绝系统规则，避免有损转换成`NO_PROXY`。官方将此开关标为实验功能，PAC只选择一条路由，不承诺与浏览器全部路由、SOCKS和故障切换行为相同；登录和认证后的请求须分别验证，配置回读不代表联网成功。见[官方系统代理范围](https://learn.chatgpt.com/docs/enterprise/managed-configuration#use-the-system-proxy-for-native-client-requests)。早期0.160实现依据保留：[代理策略](https://github.com/openai/codex/blob/rust-v0.160.0/codex-rs/http-client/src/outbound_proxy.rs)、[macOS解析器](https://github.com/openai/codex/blob/rust-v0.160.0/codex-rs/http-client/src/outbound_proxy/macos.rs)；这些源码链接不代替新增版本的运行验收。

父进程明确设置任一`HTTP_PROXY`、`HTTPS_PROXY`、`ALL_PROXY`或小写形式时，关闭完整系统解析开关并传入经过校验的显式环境，使用官方客户端原有环境语义。小写优先，大小写同步；空值原样保留，但**空值不保证直连**，仅有`ALL_PROXY`也不保证覆盖平台HTTP/HTTPS代理。锁定客户端的底层库可能补充缺失或空的分协议代理，不能把传值成功当路由证明。明确需要全部绕过时，标准`NO_PROXY=*`由客户端解释。只有`NO_PROXY`时仍选择完整系统解析；该模式下系统返回的路由优先，环境绕过只作用于官方环境回退。依据：[锁定底层环境匹配](https://github.com/hyperium/hyper-util/blob/v0.1.20/src/client/proxy/matcher.rs)。

两种模式均关闭`system_proxy_fallback`，避免登录连接失败时再用另一系统路由重发令牌请求。连接参数、每次发送前的`config/read`以及新建/恢复线程的覆盖配置都核对这两个开关；模式进入本插件会话范围指纹，模式改变不会自动恢复旧会话。旧版登记也可能因新策略指纹不同而被拒绝；原登记保留，不迁移或覆盖，可明确新建会话。不改既有专属profile模板、系统代理或全局环境。`NO_PROXY`加入三个回环主机以保护环境代理路径，官方本地回调使用直接客户端；本地MCP本身继续走已有显式回环桥接。依据：[官方登录回退实现](https://github.com/openai/codex/blob/rust-v0.160.0/codex-rs/login/src/server.rs)。

代理值只作为私有子进程环境数据，不拼接shell、命令参数或诊断；插件不读取账户凭据、聊天历史或代理认证存储。开发启动器保留父进程明确提供的八种代理变量，但不写入启动清单或普通输出。连接、登录和模型请求分别验证；匿名握手和配置回读通过不代表账户或模型网络已通过，也不自动重发用户消息。

官方0.160.0另在独立QtCore应用以真实QProcess补验启动中断开、晚到started不发送队列及实退后再连接，共26项通过。kill退出按CrashExit记录；再次初始化只证明进入写缓冲区，不证明服务应答或完整面板销毁路径。该轮没有登录或模型请求，真实回复、活动回合停止和持久历史仍待验，范围见[验证记录](VERIFICATION.md)。
