# 开源内容与隐私边界

公开仓库只保留通用实现、接口设计、公开资料来源和独立构造的中性示例。私有项目名称、业务材料、讨论内容、真实使用过程及其去标识摘要不得进入源码、文档、测试、图片、提交消息或分发包。把真实数据改名或省略路径，不改变其来源边界。

## 源码与示例

- 不纳入用户 CAD、图框、数据库、截图、安装状态、运行日志、最近工作区、请求/会话/线程标识、账号、凭据或个人路径。
- 只使用独立人工几何与虚构字段；拒绝把私有工程复制后当作测试 fixture。用于错误处理回归的合成路径和假凭据必须与真实值无关。
- 依赖使用公开 registry；不携带 URL 凭据、本地 file 依赖、用户配置或开发机器绝对路径。
- 图片核对内容、来源许可及 PNG 文本/EXIF/时间元数据；格式净化不代表图像内容匿名。公开 Study 示意图保留原开源许可与归属。
- 当前文档和聊天工具在用户调用时可能读取并传递文档、属性或图像；它们不应把输入输出、身份资料或真实使用回执写入本仓库。省略 FileName 不代表整个内容匿名。

## 实际分发物检查

源码 ZIP 只从经过审查的提交生成，不包含 .git。Addon ZIP 按固定文件白名单构建，使用纯 Python Addon 的法律说明；Node tgz 按 npm 白名单构建并包含相应 LICENSE/NOTICE。

逐成员检查实际归档的名称、内容、重复路径、大小写冲突、符号链接、路径穿越、source map、二进制元数据及法律文件。排除用户配置、缓存、编译路径、日志、数据库、备份和工程文件。最终 manifest 与 SHA-256 清单在包旁绑定来源提交及字节，不把构建成功等同于隐私通过。

## Git 与历史

当前源码树、压缩后的可达历史、实际 bundle 和已有分支/标签是不同审查范围。只检查最新文件不能证明祖先提交干净。发布候选应只包含已经逐项审查的提交与对象，并在独立恢复后核对提交链、全部对象及源码树。

旧分支、旧标签、旧包和恢复备份在重新审查前不作为可分发材料。恢复备份留在仓库外的当前用户私有目录，不进入新源码、包或公开审查记录。不要使用 --all/--mirror 代替指定干净分支发布。远端已有历史的处理必须另行评估，不能把本地候选审查说成远端已经净化。

## 使用与验证边界

本地桥接仅供可信本机环境使用；execute_script 具有本机 Python 权限，不是隐私过滤沙箱。聊天及 Desk 的连接、认证、读取和导出应通过明确的用户操作或已授权工具请求，不自动收集桌面、其它聊天、浏览器凭据或模型。

公开验证只保留能独立复现的合成测试和通用验收要求，见[验证与验收](VERIFICATION.md)。原始输出、私有检查明细和运行材料不写入 Git 或分发包；本文件不是对未检查的历史或远端的净化声明。
