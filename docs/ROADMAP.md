# 路线图

当前0.3.2候选沿用的主路线是：现有聊天通过 MCP 读取设计上下文，用常用封装或显式脚本执行任务，再核对几何、图像与文件结果。当前完整25/聊天19个工具、工作台 MVC、公开参数板、受控 STEP 和 TechDraw 演示已落地；图纸最终布局、导出和重开须在独立文档中验收，不代替生产图纸审签。验收要求见[验证与验收](VERIFICATION.md)。

## 近期：完成可重复的设计闭环

1. 逐项验收图纸布局、关联尺寸、PDF/SVG 和副本重开，扩展独立人工案例，避免仅凭接口成功判断成图可用。
2. 记录逐工具真实 MCP 和普通按钮 GUI 回归，完善公开案例，完成包清单、隐私与本地归档。
3. 将稳定高频的参数化建模、图纸和文件步骤提炼为有类型工具，补目标状态、事务、查询和恢复规则。
4. 增加 Link/装配与独立图纸案例，再按实际需求扩展特征覆盖。

普通按钮已经可以独立使用，当前 MCP 业务入口也已共用相同规则与 Controller。大型 Tool 服务适配独立推进，不作为当前轻量插件的启动前提。

## 界面语言：基础切换已实现

当前提供中文默认 / English 设置、统一界面资源和本机偏好，切换立即刷新现有界面。动态业务与原生错误全覆盖、跟随 FreeCAD 语言仍见 [TODO](TODO.md)。翻译不改变 MCP 方法、参数、命令和 Python 模块标识。

## 独立调查：FreeCAD 内嵌聊天

独立原生聊天Dock已提供官方ChatGPT登录、流式收发/中断、受控19工具及模型/字号；首行快捷图标与齿轮简化主界面。后续继续研究复用用户选择的桌面既有会话并保留历史；当前独立面板不镜像或接管该会话，也未确认稳定的同会话收发通道。

调查先确认官方支持的通信方式，再评估消息发送、结果回传、会话选择、用户授权和 GUI 线程边界。能打开网页或本机已安装客户端，不等于第三方嵌入与会话控制受到支持。若首选路径不可行，应先说明替代方式及实际成本，再决定实现方向。

不读取登录令牌，不绕过客户端访问控制，不把界面自动化当作稳定产品接口。实际会话 ID、登录状态和用户消息留在本机运行状态，不写入公开文档。该调查不阻塞原生设计和图纸能力。

## 中长期

公共 TS 规则或正式 HTTP 接口通过适配层接入，位置、版本、探测和进程生命周期单独管理。批量修改、断链修复、装配和分发见 [愿景](VISION.md)。每项先确定合同和公开验收案例，再计入可调用能力；完整阶段见 [能力计划](CAPABILITY-PLAN.md)。

版本按[统一0.3.2政策](VERSIONING.md)收敛，0.4–0.10不视为已发布版本。Label/BOM/Link原生确认源码已接入，原生端到端仍待验收；有限Pad Length源码已接入，原生验收及更多几何编辑、桌面会话复用、跨平台安装和正式发布继续保留待办，不能用当前UI或历史脚本演示替代这些门槛。
