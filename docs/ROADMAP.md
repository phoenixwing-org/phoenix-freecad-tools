# 路线图

0.2.0 的主路线是：现有聊天通过 MCP 读取设计上下文，用常用封装或显式脚本执行任务，再核对几何、图像与文件结果。当前 16 个工具、工作台 MVC、公开参数板、受控 STEP 和 TechDraw 演示已落地；图纸最终布局与导出/重开已验收，但不代替生产图纸审签。详细事实见 [验证记录](VERIFICATION.md)。

## 近期：完成可重复的设计闭环

1. 保留当前图纸布局、关联尺寸、PDF/SVG 和副本重开的验收依据，扩展更多公开案例，避免仅凭接口成功判断成图可用。
2. 记录逐工具真实 MCP 和普通按钮 GUI 回归，完善公开案例，完成包清单、隐私与本地归档。
3. 将稳定高频的参数化建模、图纸和文件步骤提炼为有类型工具，补目标状态、事务、查询和恢复规则。
4. 增加 Link/装配与独立图纸案例，再按实际需求扩展特征覆盖。

普通按钮已经可以独立使用，后续提供 MCP 业务入口时共用相同规则与 Controller。大型 Tool 服务适配独立推进，不作为当前轻量插件的启动前提。

当前为中文操作界面。简体中文 / English 切换、统一翻译资源和本机偏好尚未实现，见 [TODO](TODO.md)。翻译不改变 MCP 方法、参数、命令和 Python 模块标识。

## 独立调查：FreeCAD 内嵌聊天

目标是在工作台中增加聊天入口，优先复用本机已有聊天客户端与用户选择的现有会话，保留历史和上下文，不默认另建会话。当前尚未提供内嵌聊天面板，也未确认稳定的同会话收发通道。

调查先确认官方支持的通信方式，再评估消息发送、结果回传、会话选择、用户授权和 GUI 线程边界。能打开网页或本机已安装客户端，不等于第三方嵌入与会话控制受到支持。若首选路径不可行，应先说明替代方式及实际成本，再决定实现方向。

不读取登录令牌，不绕过客户端访问控制，不把界面自动化当作稳定产品接口。实际会话 ID、登录状态和用户消息留在本机运行状态，不写入公开文档。该调查不阻塞原生设计和图纸能力。

## 中长期

公共 TS 规则或正式 HTTP 接口通过适配层接入，位置、版本、探测和进程生命周期单独管理。批量修改、断链修复、装配和分发见 [愿景](VISION.md)。每项先确定合同和公开验收案例，再计入可调用能力；完整阶段见 [能力计划](CAPABILITY-PLAN.md)。
