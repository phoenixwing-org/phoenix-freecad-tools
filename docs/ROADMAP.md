# 后续目标

## 优先路线 零件与图纸设计

先补设计上下文，再做参数化零件与 TechDraw 出图，最后接现有 Tool/Wing。具体能力、拟定工具名、演示和验收见 [能力计划](CAPABILITY-PLAN.md)。内嵌面板不阻塞设计能力开发。

## 独立调查 FreeCAD 内嵌聊天面板

目标：在 Phoenix FreeCAD 工作台提供聊天输入、消息显示和当前模型上下文入口，减少切换应用。

优先研究借助本机已经安装的 **ChatGPT 或 Codex 客户端** 收发消息，不限定采用 ChatGPT 登录方案。首选复用本机现有客户端与会话能力；用户不希望被迫再购买独立 API 额度。

明确要求：沿用用户已存在的同一个聊天会话与会话 ID，保留历史和上下文；FreeCAD 内只是新增聊天入口，不能默认另建独立会话。实际 ID 属于本机连接状态，不提交到开源文档或示例配置。

建议用户流程：FreeCAD 面板输入 → 本机聊天客户端处理 → 通过 MCP 调用 FreeCAD 工具 → 展示结果。以下需要先做独立可行性验证，不能当作现有功能：

1. 官方支持的本机通信、插件、深链或会话接口能否满足发送与结果回传。
2. 能否复用或选择现有聊天，会话标识、消息顺序和错误如何处理。
3. 模型上下文、用户确认和 FreeCAD GUI 线程的边界。
4. 若本机客户端不提供可用通道，整理可行替代方案及实际费用后再决定。

本机安装了 ChatGPT 并不自动证明存在可供第三方嵌入的聊天接口。此阶段先调查官方支持的路径；不读取登录令牌，不绕过客户端访问控制，不把界面自动化当作已经稳定支持的集成。
