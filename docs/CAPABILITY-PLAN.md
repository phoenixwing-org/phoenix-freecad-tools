# 能力与验收计划（0.3.0）

目标是让聊天理解当前 FreeCAD 文档，并完成可核对的参数化设计与 TechDraw 工作。当前采用“常用有类型工具 + 显式 Python 脚本”两层接口，普通工作台工具独立可用。具体事实以 [验证记录](VERIFICATION.md) 为准，未注册的后续能力不进入工具清单。

## 当前能力

当前注册 21 个 MCP 工具，完整名称和 schema 见 [协议](PROTOCOL.md)。

| 范围 | 已实现 | 当前边界 |
| --- | --- | --- |
| 连接 | 离线能力、实时状态、文档列表，插件 `supported_methods` | 清单不代表运行时支持；协议仍为 v1 |
| 设计上下文 | 文档、分页对象、公开属性、当前选择 | 不提供文档实例/修订令牌，不作为写入并发校验 |
| 几何 | 现有 Shape 或 Face/Edge/Vertex 的包围盒、长度、面积、体积等摘要 | 单面体积不适用；包围盒仅为内核包络，不证明精确间隙；不重算或展开完整装配变换，不保证拓扑编号跨编辑稳定 |
| 图纸检查 | 页面、模板字段、视图和标注来源摘要 | 不修复引用、不证明尺寸完整有效或布局通过 |

| 高级执行 | GUI 主线程 Python、请求 ID 去重和状态查询 | 控制台同权限，非沙箱，不承诺异常回滚或跨重启去重 |
| 通用操作 | 明确活动文档的完整对象选择、事务显隐、受控重算 | 不自动保存；编辑/事务忙碌时拒绝 |
| Phoenix 业务 | 两阶段预览/应用，复用命名、五字段和 Link 同步的 Model/Controller | 五分钟内存 token、128KiB 完整预览；不是通用几何修订令牌 |
| 独立工作台 | 命名、五字段、Link 同步、单 MCP 按钮及中文/English 设置 | 普通工具独立可用；大型服务仍后置 |

## 公开案例的进展

| 案例 | 实测结果 | 仍需区分 |
| --- | --- | --- |
| 参数板 | 60 × 40 mm，四个 Ø6 mm 通孔，全约束草图与 Pad/Pocket；厚度 6 → 8 mm 后校核包围盒和体积 | 这是已知人工案例；通用结构化建模工具仍待封装 |
| STEP | 已知参数模型导出/导入，并重建可编辑特征后进行几何对比 | 不恢复任意 STEP 的原始特征树，不代表通用特征识别完成 |
| TechDraw | 四视图、6 mm 几何关联孔径尺寸、PDF/SVG/PNG/FCStd 导出及独立重开通过；最终布局渲染目视通过 | 仅公开人工样例，不覆盖完整生产尺寸体系或生产图纸审签 |
| 聊天接入 | 真实 MCP 连接、只读脚本及另一聊天只读联测通过 | 当前聊天的工具清单刷新与完整写入场景应分别记录 |

参数板以孔心 `(±20, ±10) mm` 和半径 3 mm 为已知输入，体积按 `(2400 − 36π) × 厚度` mm³ 对比。验收同时检查可编辑特征、完全约束状态、实体和包围盒，不能仅检查脚本返回成功。STEP 在新的测试文档保留导入几何并进行已知参数重建，不对已有工程盲目猜测特征。

本次 TechDraw 关联直径实测为 6 mm，独立重开后尺寸、模板和视图坐标保留，缩略图非单色；PDF 渲染检查确认四视图分离、引线不穿其他孔、无遮挡和越界。这是该演示布局的证据，不保证其他模型自动排版通过。

## 结构化写入的合同

后续写入不能只复用当前读取摘要作为锁或修订证明，须补齐以下设计：

- 明确目标文档、对象、预期类型及可核对状态；预览后发生变化时重新读取。
- 参数带单位，拒绝非有限值；几何引用保留来源和验证依据，模型变化后不猜接失效 Face/Edge。
- 在同一 GUI 执行步骤内校验并应用，明确编辑模式、模态窗口、现有事务及用户后续修改的处理。
- 每个可恢复步骤使用命名事务；重算、几何及图纸检查成功才提交，失败回滚能力须实测。
- 查询、去重和撤销有明确范围；已开始的超时不自动重试，也不假定已经取消。
- 文件导入、保存和导出单独规定来源、目标、覆盖及临时清理；文档事务不代替磁盘恢复。
- 默认只修改明确目标，不连带保存或关闭其他文档；跨文档任务单独设计恢复流程。

当前高级脚本由调用方自行管理上述操作边界，并不自动提供这些未来业务保证。其会话、状态和容量合同以 [协议](PROTOCOL.md) 为准。
