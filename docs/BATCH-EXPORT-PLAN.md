# 总成清单与批量输出需求方案

状态：**需求评审草案，尚未实现**。基于0.3.2候选的现有合同设计，不增加当前工具或发布宣称。本页只保存可公开的通用需求和独立中性示例，不记录实际工程、编号、使用讨论、目录、数量或验收截图。

目标流程是：**选定总成 → 生成并核对清单 → 选定输出目录 → 预览并批量输出 → 逐项验证与汇总**。普通程序不依赖AI即可执行；AI可协助解释检查结果和提出选择建议，不能替代发放、制造或原生写入确认。

## 1. 首版与非目标

首版闭环优先完成精确总成清单、筛选和**已有Drawing的PDF导出**。清单同时表达下料用途及缺图状态；单件恒厚平面轮廓的下料PDF/DXF另成一个独立交付阶段，未通过该阶段的条目明确不支持，不静默改用图页轮廓。

- 根范围是用户明确选定的总成文件和源节点，不是工作空间全部文件，也不是文件内所有对象。
- `batch.json`是唯一权威结构化清单，包含计划、人工选择、检查与执行结果。Markdown和HTML只由它生成只读视图，不再维护另一份可编辑清单；不从MD表格、HTML或文件名反向推断任务。HTML按普通文本安全转义，不执行清单内容中的脚本或角色提示。
- 源身份按图号、完整版本、变体、文件路径与源节点核对；版本和变体原样保留，不合并、不猜最高版本。
- 只生成派生输出，不覆盖FCStd、不改Link或Joint、不保存模型。输出目录独立选择；长期发放归档另配置。
- 保护用户FreeCAD、打开文档与未保存编辑。独立任务实例可以串行复用；结果未知时先查询原任务，不通过换实例重做。

首版不做任意装配修复、自动补尺寸公差、制造审签、钣金折弯展开、自动排料、共边切割、刀补、工艺参数或机床代码。采购件规格解析、完整BOM数量算法、全工作空间索引、跨平台安装和正式发行也不能因本方案而视为完成。

当前worker拒绝外部依赖、Proxy、非空表达式等不支持输入，尚不能渲染任意总成、TechDraw图纸或DXF。`create_drawing`只对受支持的单实体Part::Feature/Body创建固定A4草稿，默认不导出、不保存；结果仍要求人工复核投影。现有高级`execute_script`与GUI控制台同权、不是沙箱，不作为新批量领域接口的替代。

依据与实施边界以[协议](PROTOCOL.md)、[图纸草稿](TECHDRAW-DRAFT.md)、[worker合同](THUMBNAIL-WORKER.md)、[Desk能力共享](DESK-MCP-CONTRACT.md)、[能力计划](CAPABILITY-PLAN.md)及[验证记录](VERIFICATION.md)为准。新需求不能反向扩张这些已实现合同。单页PDF/SVG的原生副作用、预览依赖和发布实施另见[单页导出草案](TECHDRAW-EXPORT-PLAN.md)，仍未实现批量输出。

## 3. 清单范围、身份与数量

### 3.1 只沿实际使用关系展开

输入必须明确根文件及内部源节点Name。采集器区分装配发生关系、模型计算依赖和图纸引用：同一Sketch、Pad或TechDraw引用不能重复算成物理零件，Joint引用也不额外增加一件。

只沿根总成实际使用的装配实例展开。一个FCStd内可以包含多个总成、备用Body或未使用零件；未被该根引用的额外装配不进入本批次，不因与根同文件就默认输出。它们可在诊断中报告为范围外，但不改变清单数量。隐藏不自动等于不用，树上可见也不自动等于实际装配发生。

每个发生项记录从根到实例的完整节点链、实际来源、版本/变体与乘数来源。Link、数组、重复子装配、虚拟分组、抑制和循环分别处理；不能可靠展开的结构记为unknown/incomplete及原因，不用引用行数、文件数、可见对象数或圆柱面数凑数量。首版只开启已有独立样件验证过的装配类型；未知工作台/代理或失效链接停止相关计划。

根总成依赖不完整时，不把局部结果称为完整制造批次。允许只读查看问题；要执行一个明确子总成，须重新选择该子总成为根并生成自己的完整计划，不在旧计划中静默删掉未知分支。

### 3.2 精确身份与版本冲突

制造项去重键至少包含以下原始身份，不能仅按Label、图号或文件stem去重：

| 身份部分 | 规则 |
| --- | --- |
| 图号 | 保留原始字符串；缺失或互相矛盾时待审，不从相似名称猜 |
| 完整版本/变体 | 分别保存完整原值；不裁成主版本、不转成数字比较，不合并大小写或空值 |
| 来源文件 | 授权范围内的规范相对路径、所属源根、文件SHA256；同号同版本但路径/内容不同先冲突 |
| 源节点 | 内部对象Name、Body和Tip（适用时）；Label只作展示，文件hash绑定当次节点含义 |
| 制造配置 | 成品/下料等用途、明确配置与几何映射；不同制造配置不因同源文件合并 |

同一图号的多个版本可以同时出现，清单逐项保留并提示冲突；用户决定其设计意图，不自动选“最高版”。相同版本/变体的内容不同、多个Drawing均声称对应同一源、多个输出名映射到同一路径，必须在预览中明确解决后才执行。

下料变体可显式关联成品项，记录`derived_from`、用途与人工确认依据；不能从文件名后缀自动认定两者等价。成品和下料保持各自的版本、源指纹、数量及检查结果，不通过关联覆盖任何一方身份。

### 3.3 发生数量与导出次数分开

清单分开保存`occurrences`（实际发生项）与`items`（去重制造项）。嵌套装配乘数相乘，不同分支同一精确制造项的数量相加；去重输出一份PDF/DXF不把真实数量变成1。每项给出数量、单位、计算规则版本、依据发生项及完整性；缺失/未知数量为null，不能补0。首版仅支持可确认的正整数件数，长度、重量或面积用量另立数量合同。

采购件、辅助件默认不出图，仍保留发生数量、排除用途与原因。物理焊接装配可显式选择输出焊接总图，并配置其子件是否继续出图/下料；虚拟分组不是焊接件，整体采购总成也不因展开了内部文件就默认生成子件制造图。人工分类与理由必须可见，不能由AI建议直接成为制造批准。

## 4. 清单中每项需要表达的内容

| 类别 | 最少内容 |
| --- | --- |
| 范围与用途 | 精确制造身份、关联发生项、选中状态；成品/焊接/采购/辅助/下料用途及原因；成品与下料的显式关联 |
| CAD与节点 | 源根/相对路径/SHA256、内部源节点、Body/Tip、缓存/读取状态；记录磁盘与内存来源的区别 |
| 图纸 | Drawing文件与SHA256、Page内部Name与页序、关联来源、外置图框/必要资源、PDF策略及检查状态 |
| 下料 | 对应实体、轮廓来源、局部平面与坐标变换、厚度和单位、内外闭环、镜像/缩放策略、DXF1:1验证结果 |
| 数量 | 展开件数、完整性、计算依据；制造项去重与图纸/轮廓去重分别记录 |
| 人工状态 | 待审、已批准、作废、暂停及范围；机器检查通过不能改变人工审查状态 |
| 输出 | 目标根、相对目录和文件名、格式/页策略、冲突策略、所需检查及预计动作 |
| 检查与执行 | 输入/计划修订、逐项状态与固定原因码、任务身份、真实输出SHA256/字节数/页数或单位校验结果 |

待审、作废、暂停项目默认不进入制造/发放输出。明确需要评审资料时可另选“评审导出”，输出必须标为未批准，不能混入制造目录或让正式图框误表达已审签。审查状态来自有权限的显式操作或核实的正式记录；AI、文件已存在、PDF可打开或几何检查通过都不能批准它。

PDF策略须明确：已有Drawing逐页输出或同一Drawing按指定顺序合并；批准的页集合、格式、颜色与线宽保持规则，以及输出属于评审、制造还是下料核对。选“已有图纸”不自动运行缺图制图，更不暗中覆盖原图。

## 5. JSON权威清单草案

文件名暂定`batch.json`，`schema_version`从1开始，与插件版本及桥接协议分开。严格拒绝重复键、未知枚举、非有限数、绝对输出子路径、`..`穿越和超限输入；首版限制建议为10000发生项、1000制造项、2000输出、完整JSON8 MiB，超限明确停止，不裁剪成完整清单。最终预算在实现前用中性样件确认。

| 顶层字段 | 草案语义 |
| --- | --- |
| `schema_version`、`batch_id` | 合同版本与本批次不透明身份，不含项目名或用户身份 |
| `revision`、`plan_sha256` | 每次选择/映射/路径变化递增revision；hash覆盖规范化计划部分，排除自身和后续执行结果，避免自引用 |
| `root`、`sources` | 明确根节点、允许来源集合、文件/依赖指纹和读取范围；不读取最近工作空间 |
| `occurrences`、`items` | 原始发生链与去重制造项；每条关联可追溯，不反推或覆盖原版本/变体 |
| `outputs` | 逐文件格式、来源页/轮廓、目标相对路径、明确冲突策略及资格检查 |
| `decisions`、`checks` | 用户选择/审查引用与机器检查分离；pending/unknown不能变approved/pass |
| `execution` | 当前批次及逐项任务、终态、产物SHA256和部分/未知状态；不会反向修改冻结输入 |

下例全部为人工占位数据，**不是已存在的模型或可执行计划**；尖括号指纹需要由实际受限检查产生，不能直接接受为合法hash。

## 6. 核对与交互流程

建议入口为一个紧凑的“批量输出”面板。中文主按钮2–4字，保留相应英文翻译与完整悬停说明：

| 按钮 | English | 行为 |
| --- | --- | --- |
| 生成清单 | Build list | 对明确根及授权范围做有界读取，生成待审清单 |
| 核对清单 | Review | 展开差异、用途、数量、版本、缺图与阻断原因 |
| 选择目录 | Choose folder | 选独立输出根；可明确选择按总成或批次新建子目录 |
| 输出预览 | Preview | 显示本次每一源、每一页/轮廓、文件名和冲突处理 |
| 开始输出 | Export | 在批准的同revision计划上启动执行；输出预览不隐式启动实例 |
| 暂停批次 | Pause | 不再派发后续任务，当前原生调用按安全边界完成/清理 |
| 取消批次 | Cancel | 记录取消，等待自有任务与进程真实终结，保留已发布结果 |
| 继续批次 | Continue | 重新检查未执行范围；已完成不重做、未知先查询 |
| 重试失败 | Retry failed | 明确选择已确认失败项，重新预检并产生新的尝试身份 |

生成清单若需要启动独立原生只读采集实例，必须单独提示并取得相应授权；普通打开、筛选和输出预览不隐式启动。不能因此承诺仅凭磁盘索引即可取得精确依赖或真实展开数量。

主表可按用途、格式、版本/变体、待审/作废/暂停、缺图、冲突及失败筛选；勾选不改变FreeCAD树选择。行内展示完整版本、真实展开数量、输出名、检查结论与原因；摘要数字不能替代完整预览。AI可指出问题和建议筛选，不能默认勾选制造输出或替用户消除冲突。

输出根默认为**未选择**，不能沿用单文档导出“源CAD同目录”的默认规则。可记忆用户明确保存的专用导出偏好，但不能由最近空间、浏览器状态或源路径猜测；必须在本次预览完整显示。选择“按总成建目录”或“按批次建目录”只影响派生输出，不移动源文件。目录名与文件名在预览中冻结。

文件名建议包含图号、完整版本、变体及页/用途后缀。原始身份始终保留在JSON；文件系统不允许字符只按固定可追溯编码生成建议，不能默默删除版本片段。大小写不敏感、Unicode等价、保留名、同名多页和过长路径均作为冲突处理；必要时由用户选择有意义的子目录/短名，不自动覆盖或随意加数字后缀藏掉歧义。

## 7. 已有Drawing的PDF与缺图制图

### 7.1 已有Drawing优先按原样输出

Drawing→CAD/Body/Tip映射须来自实际图页/视图引用及明确关联记录，不从相似文件名猜。多个匹配需人工选择；图号或版本与来源冲突、图页引用缺失或已失效时阻断。Drawing文件、所引用源及外置SVG图框等必要资源纳入同一授权和冻结闭包；未知路径或缺资源不回退到默认图框。

保留现有图框、尺寸、公差、注释、颜色、线型、线宽、局部/剖面/辅助视图、标题栏及原有缩略图内容；不重新排版或把用户编辑的图页替换成自动三视图。已有嵌入缩略图不写回；源文件和图框字节保持。

逐页等待可核实的投影/图形准备状态，并检查页序、页面尺寸、图框、引用与关键注释。应为正的制造尺寸却报告0、视图无有效投影、关键孔/槽标注失效、字体缺失导致替代、内容裁切或空页均不能当成功。合法的坐标基准0及二维平面的零法向包络不适用这一“异常零尺寸”规则。首版对无法机器判定的完整性保留needs_review，须人工看图，不能仅凭PDF非空、页数正确或尺寸对象存在判定制造可用。

PDF输出保持彩色/单色策略和页面比例；若用户选择工艺性单色，须单独预览，不覆盖原有颜色语义。渲染字体/图框资源有明确profile与指纹；必要字体不可复现时拒绝或标记评审阻断，不扫描无关目录或静默换字体。PDF时间等生成元数据应说明其非确定性，不能预先承诺同源PDF逐字节相同；每次记录实际字节SHA256。

### 7.2 缺图单独处理

缺图项保留`DRAWING_MISSING`，用户可以排除、暂停，或进入单独“创建草稿”流程；不能把PDF按钮隐式变成模型编辑命令。创建或修改图纸仍使用相应原生完整预览/确认、单事务与撤销合同，是否保存新图纸另行明确授权，本批次不得自动保存模型来完成它。

自动投影只产生待审草稿；尺寸链、公差、螺纹、材料、表面处理、焊接要求及局部/剖面表达仍需设计者核对。当前基础三视图能力不包含这些制造完整性。草稿未完成、待审或未取得本次所需的持久源身份时，不混入制造PDF批次；经另一明确流程准备好后，重新生成清单和源指纹。

## 8. 下料PDF与DXF分开验收

下料PDF用于人工工艺核对；激光DXF是实际轮廓交付，两者有不同资格检查和终态。PDF成功不代表DXF合格，反之也不证明工艺审查已完成。不能把整张TechDraw页面、图框、标题栏或按页面比例缩放的投影视图当成激光轮廓。

首个DXF profile严格限制为**一个可确认的单件、恒厚、平面闭合轮廓**：来源是明确实体及其局部平面，记录厚度、单位、法向/基轴和到输出XY的变换。外环和所有内孔闭环完整保留，拒绝开环、自交、重复边、零长度边和无法解释的多实体/非平面/非恒厚来源；公差与曲线离散规则须版本化并接受复测。

- DXF固定毫米、1:1，验证原生/导出实体的单位声明和实际坐标；不能只写`INSUNITS=mm`就认为比例正确。
- 允许刚体旋转和平移以落到明确局部平面；镜像、实例缩放、非单位尺度及装配变换必须显式处理。首版不能可靠解释时拒绝，不把镜像件或左右件合并。
- 独立读取DXF实体与轮廓，核对闭环数、孔数/孔轮廓、净面积与包围盒，对照源平面轮廓的有限单位一致值；厚度从实体另验，不从二维线框猜。
- 中性测试须含已知100 mm基准、内孔、斜放恒厚件、左右/镜像及尺度异常；反验长宽、孔径/位置、面积和环方向/孔归属。容差阈值在profile定义中明示，越界失败，不改单位或比例“修到通过”。
- 折弯钣金、折弯补偿、K因子、展开形状、嵌套排料、共边、刀补、微连接、引入引出线和激光机工艺参数不在此profile。已有显式展开变体可作为独立来源审查，不自动生成或猜测展开。

下料PDF显示同一冻结轮廓、版本/变体、厚度、件数、单位及必要工艺提示，可有阅读比例但必须清楚标注；不能把PDF阅读比例应用到DXF。重复制造项可去重导出轮廓，但JSON保留真实件数，不把一张轮廓排布文件冒充已完成排料。

## 9. 冻结、执行、取消与安全发布

### 9.1 输入与实例归属

首版执行输入为明确授权、可信且可支持的**已保存磁盘源快照**。若根或依赖正在用户窗口中未保存，清单必须指出内存/磁盘差异及影响；不能自动保存，也不能在用户以为处理当前设计时静默读取旧磁盘版。用户可明确选择磁盘版重建计划，或退出本次执行，后续再设计经过单独验收的内存快照能力。

文件hash、真实普通文件/祖先/链接检查、依赖关系和必要资源在冻结前后反验；采集分多文件进行，不宣称跨文件读取天然是一个原子快照。变化时计划失效，重新核对，不拼接新旧依赖。复制的是原始字节，不通过FreeCAD另存为来冻结。

总成依赖镜像需保留正确相对布局并证明仅从冻结范围解析；原始绝对引用、工作台资源或外部依赖无法在不改Link/Joint的情况下受控解析时，首版拒绝。当前缩略图worker的自包含限制不能在此略过；新的装配/Drawing profile、允许列表、外部图框和字体读取须另验，不能只在打开后查看对象来宣称不可信文件安全。

只启动或复用本工具明确拥有的独立任务FreeCAD，GUI任务串行；不按PID/端口占用接管普通用户窗口，不切换用户活动文档、选择或视角。采用现有worker的进程、文档身份和资源租约原则，新增能力单独声明；目标/服务/任务归属变化时停止，不迁移到剩余实例。打开、投影、局部图页计算和关闭都可能进入native回调，受支持范围和失败后的隔离必须保守。

### 9.2 任务与恢复

每项有batch/item/output、attempt及worker/session/job身份，接受任务立即返回可查询状态；提交、查询、取消语义独立。进度分排队、冻结、打开、投影/轮廓、输出、校验、关闭、发布等阶段，展示已完成/失败/待审/取消数，不用虚假百分比掩盖原生阻塞。

暂停只阻止后续派发；取消记录意图，在安全阶段清理自有文档和stage。原生阻塞、HTTP超时、kill返回或收到取消都不是已经退出的证据；GUI与MCP两个自有child真实close前保留Native租约及冻结资源。清理不确定则隔离实例，不close-all、不关闭外来文档、不另建profile绕过未知状态。

“继续”只派发仍有效且未执行项；已确认完成的输出复核实际文件hash后复用。失败重试要有明确选择与新attempt，并重新检查源、审批、计划修订和输出冲突；unknown/in_progress/失联项先按原身份查询，不能当失败自动重发。当前worker每会话256任务、最近20结果且重启不持久的限制必须保留；新领域如使用不同预算须独立声明。Desk在结果过期前持久记录终态及产物，不让内存淘汰变成重新执行许可。崩溃后的未确认发布保留为unknown，先对照实际文件与原任务核查。

### 9.3 输出与提交点

初始冲突策略为fail，用户可明确另选目录；覆盖必须逐项展示原文件hash与新计划，默认取消。已有未知文件、目录、符号链接、硬链接异常及大小写/Unicode同名冲突保留并拒绝；不按扩展名清空目录、不按图号删除旧版本。计划绑定输出根和祖先身份，确认后变化使计划失效。

每项在自有私有stage生成和校验，确认源/计划及覆盖指纹仍匹配后才发布；支持目录fd的平台采用锚定创建、来源/目标及stage身份复核、原子link/replace与安全清理。其他平台须有独立等价合同和原生验收，不能仅凭Python函数存在宣称同等目录保证。

逐文件原子不等于整批、JSON和数据库的一次事务。新建独占批次目录时，以最终完成清单/提交标记为整套可消费边界；已有目录按逐项明确提交点发布，并把partial/unknown及已发布文件写回`batch.json`。JSON本身用受身份保护的原子替换，不把MD/HTML写出成功当批次提交。最后路径变化或持久化失败时，原目录可能已有产物；不声称“失败所以没写”，不自动重试。

取消前未发布文件只清理仍匹配归属的stage；发布后的完整文件保留并记账，不通过回滚删除用户可能已取走的成果。每个真实产物给出相对路径、MIME、字节数、SHA256与对应计划/源修订；批次仅在选定全部项目通过检查、任务终结、清理完成且结果持久化后为completed，部分完成、失败与unknown分别展示。

## 10. 统一领域接口与职责

以下只是**拟定领域操作名**，尚非现有MCP清单，也未承诺将每项直接暴露给模型：

| 操作草案 | 语义 |
| --- | --- |
| `prepare_batch_export` | 明确根/用途/输出意图，生成有界JSON计划，不执行导出 |
| `update_batch_export_plan` | 修改选择、映射与路径，校验expected revision后生成新计划；不默默改旧计划 |
| `start_batch_export` | 核批准范围、精确plan hash与输出授权，返回本次任务身份 |
| `get_batch_export_status` | 按原身份读阶段、逐项结果与摘要，不重新执行 |
| `pause_batch_export` / `cancel_batch_export` | 记录后续派发/清理意图，不谎报原生已终止 |
| `continue_batch_export` / `retry_batch_export_items` | 显式选择未执行/已确认失败项并重新预检，禁止重放unknown |

浏览器、CLI、AI/MCP和FreeCAD插件复用同一领域校验、DTO、状态与幂等规则；界面文字不同不能改变行为。浏览器通过宿主后端与Native门禁执行，不运行网页提供的任意shell/脚本；路径来自明确文件/目录授权，模型不能用`approved:true`、任意程序路径或脚本文本绕过批准。

Desk拥有批次JSON、来源授权、数量/制造分类、队列、Native协调、输出发布、缓存/数据库与长期发放记录；数据库可索引清单及协调任务，但不另维护一份能与JSON分叉的权威制造清单。Tools提供有版本的原生采集/图页/轮廓执行适配、独立任务生命周期及逐项校验结果，不直接读写Desk数据库。两侧共享稳定合同与纯算法，不复制整个服务，也不把旧XML-RPC端口替换成Phoenix HTTP就称已接通。

发放目录和长期归档有独立配置/权限/备份策略，本批次选输出目录不自动登记为设计来源或发放批准。**同类Drawing PDF不入设计库Git**。本批次新生成的其他派生产物与校验记录默认本地，专门发放归档另配置；既有权威DXF等源文件的库管理策略不在本方案中改变。本工具源码Git不接收实际产物、工程数据或运行记录；通用结论、开发待办及独立中性测试可形成开发MD。实际图纸、编号、数量、路径、审批和截图留在获授权的本地/发放存储。

## 11. 版本、错误与验收

清单、能力profile和领域API分别版本化。未知主版本只读拒绝执行；升级先预览，生成新的JSON revision与迁移记录，保留可恢复旧字节，不自动改用户已有批次。老MD/HTML不能迁移成权威计划；旧输出须按实际源、产物hash与状态重新核对，不能靠文件已存在补写成功。

错误采用固定reason code并绑定条目/阶段，例如：`DEPENDENCY_INCOMPLETE`、`SOURCE_CHANGED`、`VERSION_CONFLICT`、`DRAWING_AMBIGUOUS`、`DRAWING_MISSING`、`REFERENCE_MISSING`、`PROJECTION_NOT_READY`、`DIMENSION_INVALID`、`PROFILE_UNSUPPORTED`、`CONTOUR_INVALID`、`SCALE_MISMATCH`、`REVIEW_REQUIRED`、`OUTPUT_CONFLICT`、`TARGET_CHANGED`、`RESULT_EXPIRED`、`EXECUTION_UNKNOWN`、`CLEANUP_UNVERIFIED`。它们是草案，不直接沿用现有worker错误码作新能力声明。用户详情给出可行动的检查项，不回显任意原始异常、账户或服务身份。

验收至少覆盖：

1. **范围/数量**：根只用文件内一部分装配、未用额外装配、同件跨分支及嵌套乘数、重复来源/版本/变体、采购/辅助与焊接策略、循环和未知数组；结果不把缺失当0、不猜最高版本、不合并镜像或下料变体。
2. **快照与授权**：源/依赖/图框在生成和执行间变化、用户未保存编辑、同名重开、无效Body/Tip、未知代理/表达式和外部资源；不自动保存或碰用户选择/相机/Link/Joint。
3. **Drawing PDF**：多页顺序、完整现有图框、字体、尺寸/公差/注释/颜色和局部剖面保持；缺引用、异常0尺寸、空白/裁切及异步未就绪拒绝；逐页图像复核不能由PDF结构检查替代。
4. **下料**：已知100 mm基准与孔的恒厚件、斜放/镜像/缩放、内孔/闭环/净面积/包围盒/厚度和毫米1:1回读；非平面、非恒厚、开环、自交及整页图框输入拒绝；不暗中展开、排料或共边。
5. **发布/恢复**：新文件/覆盖取消、目录及祖先替换、目标被外改、stage源被换、发布中失败、写后回执持久化失败、批次部分取消与继续；只清自有文件，unknown不重试，逐项hash与实际字节一致。
6. **生命周期/多客户端**：相同请求幂等、异参冲突、超时查询、双实例切换/重启不迁移任务、两个child晚到close和取消时native阻塞；等待真正退出，不接管用户FreeCAD，不释放仍使用的冻结资源。
7. **客户端一致性/分发**：网页、CLI、MCP与插件对同一JSON返回同一资格与终态；原生确认不可由AI布尔值替代；实际资源/依赖许可/版本和平台验收分开，正式发行另做门禁。

所有样件独立构造；实际CAD、图纸、产物、批准与运行回执不成为公开测试数据。自动化、原生图页/输出检查、人工工艺复核和制造批准分别记录，不能相互替代。
